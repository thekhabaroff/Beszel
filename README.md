# Beszel Manager

Самостоятельный скрипт для установки и управления [Beszel Hub](https://github.com/henrygd/beszel) и Beszel Agent на сервере. Запустите команду `beszel`, чтобы открыть интерактивное меню.

## Возможности

- установка Hub и подключение Agent к Hub;
- настройка домена и обратного прокси-сервера (reverse proxy);
- просмотр состояния, журналов и обновлений компонентов;
- запуск, остановка, перезапуск, обновление и удаление Hub или Agent.

## Установка

### Одной командой

Выполните от `root` после публикации репозитория:

```sh
bash -o pipefail -c 'mkdir -p /opt/beszel && curl -fsSL https://github.com/thekhabaroff/Beszel/archive/refs/heads/master.tar.gz | tar -xz --strip-components=1 -C /opt/beszel && ln -sfn /opt/beszel/bin/beszel /usr/local/bin/beszel && /usr/local/bin/beszel --help'
```

Команда скачает архив ветки `master`, установит файлы в `/opt/beszel`, добавит `beszel` в `PATH` и выведет справку.

### Вручную

Либо склонируйте репозиторий и создайте ссылку на команду:

```sh
git clone https://github.com/thekhabaroff/Beszel.git /opt/beszel
ln -s /opt/beszel/bin/beszel /usr/local/bin/beszel
beszel --help
```

Команды установки и управления службами выполняются от `root`.

## Требования

- Debian 11 или 12 либо Ubuntu 22.04, 24.04 или 26.04;
- доступ `root`;
- Docker Engine и плагин Docker Compose. Если Docker отсутствует, мастер установки может установить его;
- для публикации Hub — домен, указывающий на сервер, и доступность выбранного способа выпуска TLS-сертификата.

Для обратного прокси можно использовать поддерживаемые конфигурации Caddy или Nginx в Remnawave либо отдельный Nginx Beszel. Отдельный Nginx запускается, только если порты `80` и `443` свободны. Скрипт не останавливает посторонние службы и не переписывает чужую конфигурацию.

## Команды

```text
beszel                         Открыть меню
beszel --help                  Показать справку
beszel --version               Показать версию
beszel status                  Показать состояние Hub и Agent
beszel status hub              Показать состояние Hub
beszel status agent            Показать состояние Agent
beszel hub <действие>          Выполнить действие с Hub
beszel agent <действие>        Выполнить действие с Agent
```

Действия для Hub и Agent:

```text
status  install  start  stop  restart  update  logs  remove
```

Например, `beszel hub logs` показывает последние журналы Hub, а `beszel agent restart` перезапускает Agent.

## Файлы и данные

| Что | Расположение |
| --- | --- |
| Скрипт и его модули | `/opt/beszel` |
| Конфигурация Hub | `/opt/beszel-hub` |
| Конфигурация Agent | `/opt/beszel-agent` |
| Файлы отдельного Nginx | `/opt/beszel-proxy` |
| Данные Hub и Agent | Тома Docker (Docker volumes) |

Файл `/opt/beszel-agent/docker-compose.yml` содержит ключи подключения Agent и создаётся с правами `0600` — читать его может только `root`.

Если после локальной установки Agent не удалось восстановить первоначальную страницу Hub, может появиться временный файл `/opt/beszel-hub/first-run-recovery.txt` с правами `0600`. Используйте его для восстановления доступа, смените пароль администратора и удалите файл.

## Сеть и безопасность

- Hub слушает `127.0.0.1:8090`. Для доступа из интернета выбранный reverse proxy направляет HTTPS-запросы на Hub.
- Agent использует сетевой режим хоста и подключает Docker socket и системный D-Bus, чтобы передавать сведения о контейнерах и службах systemd.
- Доступ к Docker socket даёт процессу Agent широкие права управления Docker на сервере. Флаг монтирования `:ro` не ограничивает команды, отправляемые через Docker API. Устанавливайте Agent только на доверенные серверы и ограничивайте доступ к его порту адресами Hub и правилами межсетевого экрана.
- Если UFW уже включён, скрипт добавляет необходимые правила Beszel. Он не устанавливает и не включает UFW и не меняет его политики по умолчанию.

## Обновление и удаление

Действие `update` загружает актуальные образы Beszel и пересоздаёт управляемые контейнеры.

Перед удалением сохраните нужные данные Hub или Agent отдельно. Действие `remove` удаляет контейнер, связанные с ним образы и тома Docker, а также локальную конфигурацию компонента. Данные из удалённого тома нельзя восстановить без резервной копии.

Agent передаёт состояние служб systemd, если системный D-Bus доступен внутри контейнера. В образ Agent не входит `journalctl`, поэтому читать журналы служб через Agent нельзя.
